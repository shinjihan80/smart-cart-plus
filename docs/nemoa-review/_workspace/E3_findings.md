- screen: 냉장고 > 음식 카드 펼침 "정보 수정" 폼 — **이번 세션 코드의 신뢰 결함**

  cause: 필드단위 즉시저장(onBlur autosave) 위에 명시적 저장버튼 UI를 덧씌움 — 두 저장모델 공존.
  fix: (권장) 즉시저장 유지+버튼을 "완료"로, 필드 변경시 마이크로 피드백(체크 200ms)+하단 "되돌리기" 스낵바 5초. (대안) draft state로 받아 "저장"에서 commit+"취소" 병치, onBlur 전부 제거.

  problem: 한 카드 안에서 같은 값이 보관기한/보관일수/유통기한 3개 이름 — 렉시콘 부재가 이번 커밋으로 3번째 단어 추가되며 악화. 한국은 2023년부터 유통기한→**소비기한**으로 법정 용어 전환됐는데 앱이 "포장에 적힌 날짜"라며 "유통기한"을 물음 — 법정용어와 실제 표기가 어긋난 채 단정.

  cause: `expiryLabel()` 단일소스가 있는데 미채택, 표시 문자열이 컴포넌트마다 리터럴.
  fix: `expiryCopy.ts`로 3단어 고정 — 날짜="소비기한"(법정용어), 잔여=expiryLabel() 반환값만, 입력보조="보관 가능 기간". 보기모드에서 "보관 일수" 행 삭제(괄호보조로 흡수: "10월3일(5일남음)"). 금지어 스캔 테스트("유통기한|보관 기한|보관 일수") 추가.
  effort: S(문자열)/M(표구조+테스트)

  fix: 지금이라도 Field.tsx+FoodAttributeFields.tsx 신설, compact prop만 다르게 같은 컴포넌트 렌더. 라벨 절대px 제거(text-2xs 토큰), 입력 최소44px, 테두리 전체 gray-200 통일(강조는 라벨 앞 인디고 바 또는 배지로). 긴 라벨은 전폭 필드로.
  effort: M

  problem: 목록의 게이지는 무조건 비교되는데 분모가 품목마다 달라 비교 불성립 — 지난 라운드 실측 그대로 미해소, 오히려 같은 D-2 수치차이로 척도오류가 더 명확해짐.

  effort: S(게이지·색)/M(포맷유틸전파+테스트)

  problem: 빈상태가 "설계된 화면"이 아니라 "데이터 빠진 화면"으로 방치 — 첫 실행 사용자가 처음 보는 카드가 고장난 것처럼 보임. 다크모드 미지원보다 부분지원(더 나쁨) — 밤에 날짜 고치는 사용자가 정확히 새 필드에서 깨진 화면을 봄.
  priority_guess: P2 (color-scheme:light 한 줄만 P1 — 새 필드가 밤에 깨짐)
  cause: 빈상태를 컴포넌트 아닌 조건부 텍스트로 처리. 라이트 전용 설계인데 브라우저에 미선언.
  fix: EmptyState 컴포넌트 표준화(아이콘+한줄안내+1차행동버튼), 칸시트엔 "이 칸에 추가하기" CTA. 주간인사이트 0일땐 차트 대신 "첫 기록을 남기면 여기에 그려져요"+버튼. `:root{color-scheme:light}` 즉시 추가(반나절, 부분다크파손 종료). 다크모드 정식지원은 별도과제(상태색토큰통일 선행 필요).
  effort: S(color-scheme·구두점)/M(EmptyState)/L(다크모드정식)
