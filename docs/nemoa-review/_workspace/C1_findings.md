## 신규 발견
- screen: 홈 "오늘 코디" 위젯 칩
  observed: DOM 실측 — 칩 폭 110px인데 텍스트 박스 68px뿐이라 "무인양품⋯/리바이스⋯/Nik"까지만 보이고 4번째(무지 울 머플러)는 카드 밖으로 잘려나감.
  problem: 홈-코디탭이 이제 같은 옷을 보여주는 건 맞는데, 홈에서는 그 옷 이름을 한 벌도 못 읽는다. 게다가 이 칩이 "오늘 입었어요" 기록 버튼이라 오식별 위험.
  priority_guess: P1

- screen: 코디 히어로 카드 라벨/부제
  observed: 제목 317px 필요/256px 박스, 부제 329px/256px — 둘 다 잘림. 4번째 아이템(머플러)은 이 화면 어디에도 이름이 안 나옴(모달 열어야 확인 가능).
  problem: 제일 공들인 카드인데 4벌 중 2벌 이름만 읽힘.
  priority_guess: P1

- screen: 알림함 내용이 실제 냉장고 상태 미반영
  observed: 샘플 데이터(오늘 만료=제주 감귤 주스) 로드 후에도 알림함은 여전히 "우유, 계란"(무관 데이터) 2건 그대로. 두 엔트리의 createdAt이 밀리초까지 패턴이 일치(예: ...T23:18:36.623Z, 날짜만 다름) — 오케스트레이터가 검증 중 수동 주입한 테스트 픽스처가 공유 브라우저 탭에 남아있던 것으로 강하게 의심됨(C8도 별도로 "옛 버전 알림함을 보여주는 캐시된 탭" 관측).
  problem: 실제 버그인지 테스트 오염인지 구분 필요 — 코드 설계상 알림은 OS 알림이 실제로 뜬 시점에만 기록되므로(권한 필요), 샘플 로드만으로는 새 알림이 안 쌓이는 게 정상 동작일 수 있음.
  priority_guess: 재검증 필요(테스트 아티팩트 가능성 높음, 코드 버그 아닐 가능성 큼)

- screen: 홈 "지금 가을철 식탁" 카드
  observed: "무항생제 달걀 15구·고등어 자반·청송 사과 5kg"(294px 필요)가 193px 박스에서 잘림, 이 화면에서 가장 큰 글씨(15.75px/700)인데도 잘림.
  priority_guess: P2
