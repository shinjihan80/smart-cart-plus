## 핵심 발견 — 데이터는 다양한데 시각은 그대로
- screen: 코디 탭 히어로 캐러셀 1/6~6/6
  observed: aria-label로 정밀 대조한 결과 실제 데이터는 카드마다 다름(1: 무인양품 옥스포드 셔츠·리바이스 501 데님·Nike 에어포스1 / 2: …에잇세컨즈 슬랙스·아디다스 스탠스미스 / 3: Maison Kitsuné 스웻셔츠·…·버켄스탁 아리조나 / 5: 코스 베이직 화이트 티·룰루레몬 요가 레깅스·아디다스 스탠스미스) — P0-48 데이터 다양성 자체는 확실히 해소. 그러나 콜라주 이모지는 6장 내내 👕(상의)/👖(하의)/👟(신발)로 거의 고정 — SlotBox가 `item.imageUrl` 없으면 `getFashionCategoryTone(item.category).emoji`로 **카테고리 단위** 이모지를 쓰기 때문에, 폴로·스웻셔츠·화이트티가 전부 같은 👕로, 러닝화·샌들·스니커즈가 전부 같은 👟로 렌더됨.
  problem: 마케터 육안으로는 "안 고쳐진 것"과 구분이 안 됨 — 추천 다양성은 실제로 달성했지만 그걸 보여주는 시각 언어(카테고리 이모지)가 애초에 아이템 단위 구분을 못 함. 사진(imageUrl)을 등록한 사용자는 이 문제가 없음 — 샘플/무사진 데이터의 근본 한계.
  lens: 옷 표현이 조악하지 않은가
  priority_guess: P1 (버그 아님, 별도 백로그 — 이모지 폴백을 카테고리 단위에서 더 세분화하거나, 사진 등록 유도 강화)
  note: 이전 라운드 "6장 넘겨도 똑같은 코디" 지적의 데이터 원인(outfitMatcher)은 완전히 해소됨. 이번 발견은 그와 무관한 별도 원인(시각 표현).
