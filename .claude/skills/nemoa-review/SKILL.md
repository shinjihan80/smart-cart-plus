# nemoa-review — 페르소나 검토 오케스트레이터

## 실행 모드

**서브 에이전트 팬아웃/팬인.** 검토자들은 서로 통신하지 않는다 — 같은 대상을
독립적으로 보고 각자 finding을 반환하면, 오케스트레이터가 병합·판정한다.
검토자 간 실시간 조율은 이득이 없고(각자 고정 페르소나), 13인 팀 통신은 오버헤드만 크다.

모든 서브 에이전트 호출에 `model: "opus"` 를 명시한다.

## 검토 대상 기본값

- 라이브 웹: `https://nemoa.vercel.app` (기준 커밋 `357fe2c`)
- Android 앱: 1.0.1 (versionCode 2, 프로덕션)
- 사용자가 스크린샷 묶음 / 특정 경로 / 기능 설명서 / diff 를 주면 그것으로 대체.
- `docs/nemoa-review/수정목록.md` = 과거 아카이브(Phase 7) 기반 기존 목록. 병합 대상이지 검토 대상 아님.

## Phase 0: 컨텍스트 확인

1. `docs/nemoa-review/_workspace/` 존재 여부 확인.
   - 없음 → **초기 실행**
   - 있음 + 사용자가 "특정 페르소나/영역만 다시" → **부분 재실행** (해당 에이전트만)
   - 있음 + 새 대상/빌드 제공 → **새 실행** (`docs/nemoa-review/_workspace/` → `_workspace_prev/` 이동 후 진행)
2. `docs/nemoa-review/수정목록.md` 를 읽어 기존 최대 ID(P0-n/P1-n/P2-n)와 "열림" 항목을 파악.
3. 검토 대상·범위·모드를 확정한다. 불명확하면 사용자에게 1회 확인:
   - 대상(기본: 라이브 사이트) / 범위(기본: 홈·냉장고·옷장·마이·등록·요금제) / 모드

## Phase 1: 모드 선택

| 모드 | 패널 | 용도 |
|------|------|------|
| **quick** (기본) | C1, C4, C8 + C2 또는 C9(대상에 따라) + E1·E2·E3 = 7인 | 일상 검토, 단일 화면/기능, 빠른 회수 |
| **full** | C1~C10 + E1·E2·E3 = 13인 | 릴리스 전 종합 검토, 대규모 변경 |
| **expert-only** | E1·E2·E3 = 3인 | 구조/코드/디자인 시스템 집중 |
| **custom** | 사용자 지정 키 | 특정 이슈 추적 |

quick 모드 대표 선정 규칙: 대상이 옷장·코디 중심이면 C2·C6 포함, 결제·통계 중심이면 C7 포함, 접근성 이슈 추적이면 C8·C9·C10 포함.

## Phase 2: 팬아웃 실행

1. 검토단 에이전트를 병렬 호출 — 각 페르소나 키마다 1개, `run_in_background: true`:
   ```
   Agent(subagent_type="nemoa-customer-reviewer", model="opus",
         prompt="persona_key=C8, target=https://nemoa.vercel.app, scope=<범위>")
   ```
2. 검토단 완료 후, 전문단 에이전트를 병렬 호출 — `customer_findings` 로 검토단 결과 묶음을 전달:
   ```
   Agent(subagent_type="nemoa-expert-reviewer", model="opus",
         prompt="expert_key=E2, target=..., scope=..., customer_findings=<파일 경로>")
   ```
   (expert-only 모드면 이 단계만 실행)
3. 각 에이전트 결과를 `docs/nemoa-review/_workspace/{key}_findings.md` 로 저장.
4. 재시도 정책: 실패한 에이전트는 1회 재호출. 재실패 시 그 페르소나 없이 진행하고 리포트에 "누락: {key}" 명시.

> 13인 동시 실행이 무거우면 검토단을 2배치(C1~C5 / C6~C10)로 나눠 호출한다.

## Phase 3: 팬인 — 병합·판정

1. 전 `docs/nemoa-review/_workspace/*_findings.md` 를 읽는다.
2. **중복 병합**: 같은 화면·같은 문제는 한 항목으로 합치고 "근거 페르소나"에 모든 키를 모은다. 표현이 달라도 본질이 같으면 병합.
3. **우선순위 판정** (`references`는 nemoa-persona-review 스킬 `output-schema.md`):
   - 화면 간 수치 불일치 / 카피↔동작 모순 / 크래시·빈 화면 / 결제·데이터 오류 → **P0**
   - 서로 다른 페르소나 3인+ 지적, 또는 전문단 2인+ "신뢰 훼손" → 최소 **P1**, P0 검토
   - 진입 혼란·온보딩·공포 유발·핵심 흐름 마찰 → **P1**
   - 아이콘·타이포·대비·다크모드·빈 상태·카피 다듬기 → **P2**
4. **상충 병기**: 전문가 해결안이 상충하면 삭제하지 말고 "안 A(E1) / 안 B(E3)" 로 함께 적고 트레이드오프를 한 줄 덧붙인다.
5. **난이도**: 전문단 effort 값의 합의치(다르면 큰 쪽).

## Phase 4: 산출물

1. `docs/nemoa-review/수정목록.md` Part 4 표에 **병합**:
   - 신규 이슈 → 기존 최대 번호 다음 ID 발급 (`P1-12` 등)
   - 기존 이슈와 동일 → 그 행의 "근거 페르소나"에 키 추가, 상태 갱신, 해소됐으면 "완료"
   - Part 3(화면→문제→제기자) 표에도 신규 행 추가
2. 문서 상단 또는 별도 `docs/nemoa-review/_workspace/review_{날짜}.md` 에 검토 리포트 헤더 작성 (형식: output-schema.md §4).
3. 사용자에게 요약 보고: 신규 P0/P1/P2 개수, 상태 변경 건수, 가장 시급한 3건, 상충 항목.
4. 최종 문서를 사용자에게 전달(SendUserFile).

## Phase 5: 피드백

보고 후 물어본다: "페르소나 구성이나 판정 기준에서 바꿀 점 있나요?"
- 결과 품질 → `nemoa-persona-review` 스킬 수정
- 페르소나 렌즈·추가/삭제 → `references/roster.md` + 해당 에이전트
- 판정 기준·모드 → 이 오케스트레이터
- 변경은 `CLAUDE.md` 변경 이력에 기록.

## 에러 핸들링

| 상황 | 처리 |
|------|------|
| 에이전트 실패 | 1회 재시도 → 실패 시 누락 명시하고 진행 |
| 대상 URL 접근 불가 | 사용자에게 알리고 스크린샷 대체 요청 |
| finding 0건(전 패널) | 대상·범위가 맞았는지 사용자 확인 |
| 기존 목록 파일 없음 | 새로 생성(Part 4만이라도) |
| 상충 해결안 | 병기, 삭제 금지 |

## 테스트 시나리오

**정상**: "네모아 라이브 사이트 quick으로 검토해줘" → Phase 0 컨텍스트 확인 → quick 7인 팬아웃 → 병합 → `docs/nemoa-review/수정목록.md`에 P1-12~ 추가 + 리포트.

**에러**: "결제 흐름만 full로" 인데 C5 에이전트 2회 실패 → C5 제외 12인으로 병합, 리포트에 "누락: C5(정민우)" 명시, 결제 관련 P0 후보를 사용자에게 강조.
