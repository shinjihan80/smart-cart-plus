# 산출물 스키마

## 1. finding 레코드 (에이전트 1인이 반환)

각 발견을 아래 형식으로. 마크다운 표 또는 리스트, 필드명은 고정.

```
- persona: C7 (오세훈 45 / 실용주의 가장)
  screen: 마이페이지 > 요약 탭
  observed: "소진 처리(누적) 0건", 종합통계 지출 항목 없음
  problem: 앱이 실제로 아껴준 게 뭔지 증거가 없어서 계속 쓸 이유를 못 느낌
  lens: "이게 돈을 아껴주냐"
  priority_guess: P1
  # 전문단만:
  cause: 절약 지표를 집계·표시하는 화면이 설계에 없음
  fix: "이번 달 아낀 금액 / 안 버린 음식 N개"를 홈·마이 상단 카드로. 데이터 누적 전엔 예상치+설명.
  effort: M
```

필수 필드: persona, screen, observed, problem, priority_guess
전문단 추가 필수: cause, fix, effort (S=반나절 / M=2~3일 / L=1주+)

## 2. 우선순위 기준 (오케스트레이터 최종 판정)

| 등급 | 정의 | 신호 |
|------|------|------|
| **P0** | 신뢰를 깨는 버그·모순. 출시 전 필수. | 화면 간 수치 불일치, 카피↔동작 모순, 크래시·빈 화면, 결제·데이터 관련 오류 |
| **P1** | 이탈·오해를 부르는 UX. 다음 스프린트. | 진입 혼란, 온보딩 부재, 공포 유발, 핵심 흐름 마찰, 3인 이상 페르소나가 지적 |
| **P2** | 완성도·톤·접근성. 지속 개선. | 아이콘·타이포 일관성, 대비·터치타깃, 다크모드, 빈 상태, 카피 다듬기 |

승급 규칙: 서로 다른 페르소나 3인 이상이 같은 문제를 지적하면 최소 P1. 전문단 2인 이상이 "신뢰 훼손"으로 분류하면 P0 검토.

## 3. 통합 수정 목록 (최종)

기존 `docs/nemoa-review/수정목록.md` Part 4 표에 **병합**한다. 덮어쓰기 금지.

| 열 | 규칙 |
|----|------|
| ID | `P0-9`, `P1-12` … 기존 최대 번호 다음부터 발급 |
| 영역 | IA / 카피 / 통계 / 광고 / 요금제 / 냉장고 / 옷장 / 데이터 / 온보딩 / 접근성 / 디자인시스템 / 알림 / 프로필 / 개인정보 / 문의 |
| 수정 내용 | 한 문장 명령형. 무엇을 어떻게. |
| 근거 페르소나 | 제기한 키 나열 (예: `C7, C8, E2`) — 많을수록 우선순위 신호 |
| 상태 | 열림 / 수정중 / 완료 / 보류 |
| 난이도 | S / M / L (전문단 합의값) |

기존 항목과 동일 이슈면 새 ID를 만들지 말고 기존 행의 "근거 페르소나"에 키를 추가하고 상태를 갱신한다.

## 4. 검토 리포트 헤더 (매 실행)

```
# 네모아 페르소나 검토 — {대상} — {날짜}
- 검토 대상: {스크린샷 N장 / URL / 빌드 해시 / 기능명}
- 참여: 검토단 {N}인, 전문단 {N}인 (모드: quick / full)
- 신규 발견: P0 {n} · P1 {n} · P2 {n}
- 기존 항목 상태 변경: {n}건
```
